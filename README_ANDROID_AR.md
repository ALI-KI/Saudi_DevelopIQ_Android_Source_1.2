# Saudi DevelopIQ — نسخة أندرويد (مرحلة الاختبار الهندسي)

الإصدار الحالي: **1.2.0 — مراجعة انطباق نظام البناء على القطعة**.

هذه الحزمة **تحتوي على مصدر التطبيق الكامل المعدّل لأندرويد** المأخوذ من ZIP نسخة الكمبيوتر. لم يتم إثبات جاهزيتها للنشر أو اعتمادها بديلًا هندسيًا عن اللوائح الرسمية. تحتوي على ملف GitHub Actions يبني APK تجريبيًا عند تشغيله؛ الحزمة نفسها ليست APK.

## ما نُقل وحُسّن

- واجهة هاتف مستقلة في `src/mobile/`، مع التنقل أسفل الشاشة، صفحات الأرض والتطوير والمواقف والمالية والأنظمة والسيناريوهات والتقارير والإعدادات.
- إعادة استخدام المحركات الحسابية الموجودة في `src/core/engines.ts` مع إصلاحات للحالات الحدية واحتساب مواقف الواجهة ضمن العرض التقديري فقط إلى أن يؤكد المستخدم عددها.
- الحفظ داخل مساحة التطبيق الخاصة باستخدام Capacitor Filesystem، مع تدوير نسختين محليتين وكشف فساد بيانات النسخة.
- تصدير تقارير Excel وPDF باستخدام المكتبات الموجودة، مع مشاركة الملف من أندرويد، وتصدير/استيراد نسخ JSON.
- الاحتفاظ بالهوية الرسمية من `assets/brand/` وإنشاء صور أيقونة أندرويد والـSplash من الشعار الموجود.
- عدم نقل ملفات `node_modules` أو `dist` أو `release` من نسخة الكمبيوتر.

## الجديد في الإصدار 1.2 — منع اختيار نظام بناء اعتباطي

- إنشاء الدراسة يبدأ **بلا نظام بناء**؛ يتم تحديد القطعة أولًا ثم الانتقال إلى شاشة الأنظمة.
- مقارنة الحزم المرشحة بحسب الاستخدام والنطاق المكاني المدوّن، مع إظهار المصادر والإصدارات والتصنيف العام/الخاص إذا كان موثقًا في البيانات.
- الحزم التجريبية وغير المطابقة لا يمكن ربطها بدراسة فعلية.
- لا يمكن ربط حزمة دون رقم مستند محدد للقطعة، وتفسير انطباق، واسم مراجع، وحسم أولوية الأنظمة إن تعددت.
- يحفظ دليل الاختيار مع السيناريو، ويُلغى عند تغيير بيانات القطعة المؤثرة؛ لا تعتبر الشهادة المدخلة من المستخدم تحققًا رسميًا.
- يعرض تقرير PDF/Excel والقرار الاستثماري تحذيرًا صريحًا بأن انطباق النظام على القطعة لم يُتحقق منه رسميًا داخل التطبيق.
- أضيفت اختبارات حماية في `src/core/regulationSelection.test.ts` وشرح كامل في `REGULATIONS_APPLICABILITY_WORKFLOW_AR.md`.

**القيود:** معظم المكتبة الحالية مراجع مستخدم وليست قاعدة تنظيمية رسمية متكاملة. النظام لا يختار قانونيًا بناءً على الحي فقط، ولا يدعي التأكد الآلي من الانطباق دون مستند أو تكامل مع الجهة المختصة.

## إنشاء APK بواسطة GitHub Actions

1. أنشئ Repository جديدًا على GitHub، مثلاً `Saudi-DevelopIQ-Android`، ويفضّل Private خلال الاختبار.
2. فك الضغط وارفع **محتويات المجلد** إلى جذر المستودع، بما فيها المجلد المخفي `.github/workflows`. لا ترفع ملف ZIP داخل المستودع دون فكّه.
3. إذا تستخدم Git على جهازك، افتح PowerShell داخل هذا المجلد واكتب:

   ```powershell
   git init
   git add .
   git commit -m "Saudi DevelopIQ Android test build"
   git branch -M main
   git remote add origin https://github.com/USERNAME/Saudi-DevelopIQ-Android.git
   git push -u origin main
   ```

   استبدل `USERNAME` باسم حسابك، وتأكد أنك أنشأت المستودع بنفس الاسم وأن دخول GitHub مضبوط. في حال عدم وجود Git مثبت، استخدم GitHub Desktop لإنشاء المستودع ونشره من هذا المجلد.
4. افتح **Actions** في المستودع، اختر **Saudi DevelopIQ - Android APK** ثم **Run workflow**.
5. بعد نجاح جميع المراحل، افتح صفحة التشغيل الناجح ثم **Artifacts** وحمّل `SaudiDevelopIQ-Android-APK` وفك ضغطه، ستجد `app-debug.apk`.
6. ثبّت ملف APK على هاتف أندرويد للاختبار، وامنح إذن التثبيت من هذا المصدر إذا ظهر الطلب. هذه نسخة **debug موقعة بمفتاح Android تجريبي**، وليست إصدار متجر Google Play.

قد يحتاج تفعيل GitHub Actions من إعدادات المستودع. لا تحتاج Android Studio على جهازك عندما يتم البناء على GitHub.

## اختبار التطبيق بعد التثبيت

تحقق من: تشغيل أول مرة بدون مشروع افتراضي، إنشاء دراسة بلا نظام، إدخال رقم المخطط والقطعة والمساحة والشوارع، مقارنة أنظمة البناء، توثيق مستند خاص بالقطعة، تعديل السيناريو، حساب FAR والارتدادات، عجز المواقف، التكاليف والبيع، حفظ/إعادة فتح بعد إغلاق التطبيق، النسخ الاحتياطي والاستعادة، PDF وExcel فعليًا عبر قائمة المشاركة، لغة الواجهة، والوضع الداكن. الأرقام التنظيمية غير الرسمية تبقى **بيانات مرجعية وليست معتمدة**.

## القيود المعروفة

- لا توجد قاعدة SQLite ويندوز نفسها داخل أندرويد؛ التخزين الجديد ملفات JSON في مساحة التطبيق الخاصة. استيراد بيانات Windows مباشرًا من ملف SQLite **غير مدعوم**. يمكن تطوير محول لبيانات النسخ الاحتياطية إن لزم.
- تعدد اللغات موجود جزئيًا في أسماء القوائم والحقول؛ هناك نصوص عربية لم تُترجم بعد للإنجليزية بشكل كامل.
- الإخراج الرسمي لـPDF يعتمد على Canvas، ويحتاج مراجعة بصرية للعربية وجودة الصفحات على الهاتف قبل التوزيع.
- التقدير الهندسي والجدوى يعتمد على مدخلات وافتراضات قابلة للتعديل، وليس إثباتًا لنظام بناء معتمد.
- نتيجة Build عبر GitHub Actions، واختبار التثبيت والأداء على أندرويد، ما زالت **غير متحققة** في بيئة إعداد الحزمة.

## أوامر المطوّر

```bash
npm install
npm run mobile:check
npx tsc --noEmit
npm run test
npm run mobile:build
npx cap add android
npx @capacitor/assets generate --android
npx cap sync android
cd android && ./gradlew assembleDebug
```

الأمر الأخير يتطلب Android SDK/JDK محليًا، أو استخدام GitHub Actions بدلًا منه.
